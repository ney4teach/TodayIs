# План разработки Today Is

Дата: 26 ноября 2026 года.

Статус: рабочий план для согласования. Сроки и состав первого релиза уточняются после первичной проверки.

## Цель ближайшего релиза

Подготовить расширение к тестированию небольшой группой знакомых: удобная новая вкладка, понятные настройки, стабильное сохранение данных и простая установка.

До завершения этого этапа не расширять набор виджетов. Сначала довести существующие основные сценарии.

## Исходная точка

- Расширение Chrome Manifest V3, версия в `manifest.json` — `1.0.0`.
- Обычные JavaScript, HTML и CSS, без сборки.
- Десять виджетов: приветствие, часы, поиск, погода, закладки, календарь, задачи, музыка, цитата и система.
- Реализованы сетка карточек, общее меню настроек, темы, обои и акцентный цвет.
- В проекте присутствуют облачная синхронизация, учёт активности сайтов и компонент системной музыки Windows.
- Есть тесты клиента и сервера синхронизации и workflow подготовки Telegram-анонсов.

Это результаты просмотра исходников, а не подтверждение работоспособности. Проверки интерфейса в Chrome и запуск тестов в рамках подготовки плана не выполнялись.

### Расположение проекта

Доступная копия находится в `C:\Проекты\Мастер-папка\todayIS`. В ней не обнаружен Git-репозиторий. Путь `C:\Проекты\todayIS`, указанный в `AGENTS.md`, отсутствует.

Перед разработкой нужно согласовать рабочий путь и сравнить текущую папку с репозиторием https://github.com/ney4teach/TodayIs. Текущие файлы сохранить: в них могут быть изменения, отсутствующие на GitHub.

## Приоритеты

1. Потеря данных, ошибки запуска и блокирующие сбои.
2. Закладки, сетка и размеры карточек.
3. Понятные настройки и читаемость.
4. Стабильность остальных основных сценариев.
5. Визуальная полировка.
6. Новые функции — после обратной связи тестовой группы.

## Этап 1. Зафиксировать рабочую версию

- [ ] Найти локальную Git-копию либо согласовать клонирование репозитория.
- [ ] Сравнить GitHub с текущей папкой, не перезаписывая локальные файлы.
- [ ] Определить основную рабочую папку и актуализировать инструкции.
- [ ] Зафиксировать исходную версию и известные ограничения.
- [ ] Создать единый бэклог задач и ошибок.
- [ ] Выполнить базовую проверку установки и запуска.

**Критерий готовности:** известна актуальная версия, локальные изменения сохранены, задачи собраны в одном месте.

## Этап 2. Довести закладки и сетку

- [ ] Проверить минимальный и обычный размеры каждого виджета.
- [ ] В компактных закладках показать все иконки выбранной категории целиком, без внутренней прокрутки.
- [ ] Проверить отступы между иконками и от краёв карточки.
- [ ] При необходимости скрывать второстепенные подписи, сохраняя понятность управления.
- [ ] Проверить перетаскивание и изменение размеров рядом с занятыми позициями.
- [ ] Исключить пересечения карточек и сохранить единый промежуток.
- [ ] Проверить перестроение сетки в узком окне и восстановление широкой раскладки.
- [ ] Проверить сохранение раскладки после открытия новой вкладки.

**Критерий готовности:** закладки удобны в компактном виде, сетка предсказуема и не допускает перекрытий.

## Этап 3. Упорядочить настройки и оформление

- [ ] Настройки виджетов доступны только из общего меню.
- [ ] Проверить светлую, тёмную и системную темы, включая смену темы устройства.
- [ ] Проверить ручной акцент и подбор по обоям, включая недоступность цвета изображения.
- [ ] Проверить наличие и поведение двух общих шрифтов: Segoe UI и Verdana.
- [ ] Проверить общий размер текста отдельно от масштаба карточек.
- [ ] Проверить компактные карточки с обоими шрифтами и увеличенным текстом.
- [ ] Проверить длинные подписи, пустые состояния и сообщения об ошибках.
- [ ] Проверить клавиатурную навигацию, видимый фокус и подписи кнопок.
- [ ] Проверить сохранение настроек после повторного открытия вкладки.

**Критерий готовности:** оформление единообразно, настройки понятны и не ухудшают доступность содержимого.

## Этап 4. Проверить основные сценарии

- [ ] Поиск: ввод запроса, выбор поисковика и переход.
- [ ] Закладки: пользовательские категории и источник из браузера.
- [ ] Задачи: добавление, редактирование, выполнение и сохранение.
- [ ] Календарь: выбор даты, работа с событиями и сохранение.
- [ ] Погода: геопозиция, сохранённые города, отказ в разрешении и отсутствие сети.
- [ ] Часы: форматы, часовые пояса и активность сайтов.
- [ ] Музыка: воспроизведение по ссылке и понятное состояние без Windows-компонента.
- [ ] Windows-компонент: установка, доступный медиасеанс и управление поддерживаемым плеером.
- [ ] Облако: вход, синхронизация двух профилей, работа без сети и выход.
- [ ] Проверить поведение остальных виджетов и документировать ограничения.
- [ ] Проверить консоль на ошибки в основных сценариях.
- [ ] Запустить существующие тесты:

```powershell
node --test server/client.test.mjs server/server.test.mjs
```

**Критерий готовности:** нет известных блокирующих ошибок и потери данных; неподдерживаемые возможности явно описаны.

## Этап 5. Подготовить тестовый выпуск

- [ ] Согласовать состав и порядок стартовой раскладки.
- [ ] Проверить установку в чистом профиле Chrome.
- [ ] Проверить набор запрашиваемых разрешений и понятность их назначения.
- [ ] Подготовить пакет расширения без серверных секретов и ненужных файлов разработки.
- [ ] Актуализировать инструкцию установки и известные ограничения.
- [ ] Определить канал обратной связи и шаблон сообщения об ошибке.
- [ ] Для заметных изменений подготовить текст и сценарий скриншота Telegram-анонса.
- [ ] Согласовать передачу версии тестовой группе.

**Критерий готовности:** новый пользователь может установить расширение и начать работу по инструкции без нашей помощи.

## Этап 6. Обработать обратную связь

- [ ] Собирать сообщения пользователей в единый бэклог.
- [ ] Для каждой ошибки фиксировать воспроизведение, окружение и влияние.
- [ ] Сначала устранять частые и блокирующие проблемы.
- [ ] Выпускать небольшие проверенные обновления.
- [ ] По результатам тестирования определить следующий релиз и необходимость новых функций.

**Критерий готовности:** основные сценарии подтверждены тестовой группой, приоритеты следующего релиза основаны на обратной связи.

## Организация работы

- Основной чат ведёт продуктовый план, общие файлы, интеграцию и выпуск.
- Работы по отдельным виджетам можно вести в отдельных чатах и ветках.
- Изменения общих настроек и формата данных согласовываются в основном чате.
- Делегирование агентам запускается только по явному запросу или применимым инструкциям.
- Перед правками проверяются манифест, ветка и незакоммиченные изменения.
- Чужие локальные изменения не удаляются и не перезаписываются.
- Каждая завершённая задача публикуется отдельным PR либо обновлением PR задачи после локальной проверки.
- Слияние в main и публикация пользователям требуют согласования.

### Что должно быть в задаче

1. Пользовательская проблема и ожидаемая польза.
2. Границы изменения: что делаем и что не входит.
3. Критерии приёмки.
4. Зависимости и риски.
5. Сценарии проверки.

### Когда задача считается завершённой

- Реализация соответствует критериям приёмки.
- Проверены затронутые сценарии; отдельно указано, что не проверено.
- Для визуальных изменений проверены минимальный и обычный размеры, светлая и тёмная темы, оба шрифта и увеличенный текст.
- Для сетки проверены узкое окно, перетаскивание и изменение размера у занятого места.
- Для настроек проверено сохранение после повторного открытия вкладки.
- Изменения оформлены коммитом и PR с результатами проверок.
- Для заметного обновления в PR есть раздел «Для подписчиков» и проверенный сценарий скриншота согласно AGENTS.md.
- Пользователю передана ссылка на PR. Публикация анонса в канал отдельно согласована.
