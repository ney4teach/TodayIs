# Работа над Today Is

Эти правила действуют во всём репозитории проекта GNTD (Today Is).

## Ответственность

- **Основной чат проекта** — этот чат, в котором пользователь поручил перенос Today Is на GitHub. Он отвечает за весь репозиторий, общую архитектуру, интеграцию изменений, качество основной ветки и документацию. Здесь решаются задачи, затрагивающие несколько независимых частей проекта.
- **Тематический чат** отвечает за участок, который пользователь поручил ему в этом чате. Например, чат музыки ведёт музыкальный виджет и его Windows-компонент, чат погоды — погодный виджет и прогноз, чат закладок — категории и плитки сайтов.
- В общих файлах, включая `newtab.js`, `newtab.css` и `manifest.json`, тематический чат меняет только фрагменты, необходимые для своей задачи. Если решение требует изменить поведение другого виджета или общий контракт данных, передайте основному чату описание зависимости и требуемого изменения.
- Когда пользователь явно меняет границы задачи или распределение ответственности, применяйте его актуальное поручение.

## Совместная работа

- Перед правками сверяйте состояние рабочей копии и актуальную ветку. Сохраняйте изменения других чатов, особенно в общих файлах.
- Группируйте изменения по задаче. Для параллельной работы используйте отдельные ветки и передавайте результат на интеграцию с кратким описанием изменённых файлов и проверок.
- Проверяйте затронутый сценарий через обычную точку входа. Для изменений запуска панели проверьте отрисовку при открытии новой вкладки. Для облачной синхронизации выполните тесты из README.
- Поддерживайте README в соответствии с поведением проекта. Храните OAuth-секреты, токены, базы профилей и локальные сборки вне Git.

## Черновики анонсов в Telegram

Для каждого обновления, которое заметят пользователи, подготовьте текст и кадр как часть работы над фичей.

- В описании PR добавьте раздел `## Для подписчиков`. В двух-трёх предложениях расскажите, что изменилось, чем это полезно и где попробовать. Пишите по-русски и о сделанном: «Добавили», «Обновили», «Исправили». Результаты тестов, команды, откат и другие технические детали вынесите в отдельный раздел. В тексте для подписчиков не должно быть ссылок на GitHub.
- Проверьте сценарий скриншота на версии расширения из PR. Кадр должен показывать само изменение на тестовых данных. Если общего кадра новой вкладки достаточно, используйте `auto`. Если в общем кадре изменение не видно, добавьте или обновите сценарий в `.github/workflows/telegram-draft.yml` и настройте его автоматический выбор для PR. Для поиска показывайте строку и управление поисковиком, для обоев — настройки оформления и результат.
- При завершении задачи передайте пользователю ссылку на PR. В GitHub Actions → «Подготовить пост» → Run workflow пользователь вставляет её в `source`. `screenshot` остаётся на `auto`, `summary` и `image_url` остаются пустыми. Бот присылает текст и скриншот в личку для просмотра. Публикация в канал требует отдельного решения.
